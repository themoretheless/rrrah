# Prepared native CR3 source for cold-prefetch byte admission

NativeCr3Decoder.prepare now returns an owning PreparedCr3. It performs the existing bounded/cancellable compressed-file read and structural frame parse, validates the full-sensor u16 byte lower bound and stops before entropy decoding or sensor allocation. The object owns the original encoded PixelBuffer and cloned request/cancellation token. Its Debug output exposes sizes, not source pixels. Drop releases encoded credit; consuming decode reuses that immutable source snapshot. Structural parsing currently repeats to rebuild borrowed frame views, but the source file is not reread. Timing fields include preparation parsing.

Cold RAW prefetch uses this API only for the current native CR3 backend (EOS R8 scope). After persistent cache miss, source-headroom check and gate acquisition, it queries actual sensor bytes against protected RAM membership. A too-large sensor is skipped with (false,None) while dropping encoded ownership. If admitted, the same source owner enters the existing decoder. Existing RAM hits bypass preparation; other RAW formats retain their original path. This is not a new format/variant qualification and no LibRaw/runtime dependency is introduced.

The original navigation regression now also includes a partially available byte policy: selected+nearest occupy2W while cache limit is2.5W. The additional W-byte sensor cannot fit until the nearest lease is released. Both navigation directions pass unchanged managed sensor peak for blocked far work, full ready-frame pressure hit, subsequent admission and final release. All staged nearest sensor values and metadata match the ordinary decoder. Cases with exact protected byte exhaustion and count pressure remain covered.

A separate original-source ownership test copies only the existing local fixture into a disposable directory, prepares it, removes that owned temporary copy and decodes successfully. Every sensor value/metadata matches normal decoding, proving no dependency on reopening that path. Managed preparation usage equals encoded bytes only; peak equals encoded+sensor bytes. Cancellation after preparation and dropping without decode return to zero. No source media is checked in with this report. These are same-decoder comparisons, not a new independent pixel/color oracle.

CI guards cover cancellation/selection before source I/O, malformed-container cleanup after encoded admission and zero-budget refusal. Native backend unit subset:7 passed,1 ignored; ordinary application suite:292 passed,83 ignored; original-source manual cases:2 passed. Formatting and whitespace checks pass.

Limits: existing parser metadata/scratch and baseline reference allocations are not total-RSS accounting. Only cold CR3 misses use exact geometry admission; partial-space persistent/swap hits and other formats are not given a new estimator. Structural preparation adds parsing work on fitting cold sources; throughput/latency overhead has not been measured, so no speedup is claimed. The new path is qualified for admission, ownership and sample preservation, not general performance.
