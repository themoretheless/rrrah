# Zero-copy PNG EXIF source adapter

The still-raster PNG route parses orientation directly from borrowed EXIF source bytes and supplies a virtual Read/BufRead/Seek stream omitting the natively handled eXIf chunk. No source bytes or CRC fields are modified; no replacement PNG is constructed. Chunk removal shifts only the virtual stream position, not physical input data. The existing borrowed TIFF-EXIF orientation parser is reused. ICC/text policies remain unchanged.

EXIF CRC is checked with the existing optimized flate2 CRC utility in at most65536-byte pieces with cancellation checks. Duplicate, truncated, bad-CRC and post-IDAT EXIF are explicit typed errors. PNG Third Edition Table7 requires one eXIf before IDAT: https://www.w3.org/TR/png-3/#5ChunkOrdering . Existing tolerant behavior for unrelated malformed framing is deferred to the pixel decoder, preserving its admission order. Invalid EXIF CRC/order is now rejected explicitly rather than silently ignored by the old ancillary-metadata path.

Tests verify exact source reconstruction without EXIF, every logical byte position, start/end/current seeks, seeks beyond EOF and invalid negative seeks, immutable original input, and exact independent Rotate90 pixel permutation under the public raster wrapper. Native pixel-overlap credit peaks2048 bytes and retains1024 (codec-private buffers excluded). The late-EXIF control is rejected instead of reinterpreted as a valid PNG. All existing8/16-bit EXIF permutation/ICC/pixel/color controls remain green. Cancellation during a4MiB EXIF CRC stops after the first64KiB piece, preserves source and permits retry.

A test-only allocator probe on synthetic4MiB-padded EXIF compares the same current image decoder with a normal Cursor versus the virtual source. Caller input/output and pixel rotation are outside this metadata/pixel-decode measurement. Native preparation: **0allocations /0heap bytes**. Normal source: **12610578 requested heap bytes peak /23 allocations**; virtual source: **27768 bytes /6 allocations**. Both return the same Rotate90 orientation and exact underlying pixel bytes; all measured private allocations release. These are allocation requests, not RSS or latency results. Source generator, raw logs and linked library hashes are retained; large files stay under/tmp.

Public decoder: **214 passed /5 ignored /zero failures**. Viewer: **285 passed /80 ignored /zero failures**. PNG pixel decoder fixed tables and row/unfiltering buffers still need shared-root accounting; APNG's direct metadata path and embedded PNG consumers are separate. No complete PNG/100-format or physical HDR/NVIDIA qualification claim.
