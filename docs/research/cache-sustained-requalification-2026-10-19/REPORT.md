## Failed assertion corrected without relaxing cache requirements

Initial100kMetal test failed because it unconditionally unwrapped three neighbour preloads while the visible frame and nearest lease exhausted the two protected count slots. Production intentionally refuses farther cold prefetch before decode; the existing protected_count_slots_skip_far_decode_but_keep_hits_and_retry_after_release regression verifies this contract. Accepting all three would violate the configured count/priority contract.

The large-collection test now accepts only the exact all-count-slots-protected error after the nearest neighbour; requires exactly two resident slots, a retained nearest lease and unchanged root usage/resident bytes/count; every other error still fails. The nearest lease must succeed, remain the same shared pixels and hit without decode; visible pixels/full-pressure hit and cancellation checks remain. At least one refusal must occur. Re-run recorded1022expected refusals across512steps and passed on Metal. Initial failure and corrected run are preserved; this is a qualification-test correction, not a production cache fix or larger budget.
