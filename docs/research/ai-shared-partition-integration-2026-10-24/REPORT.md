## Representation and transaction

Keep/subtract use a statically dispatched sink interface. The normal release sink is the existing AdmittedVec; the experiment uses chunk/segment storage. Unchanged carry ranges clone chunk handles instead of materializing Fragment arrays. New/changed fragments append to a uniquely owned tail; shared partial tails use bounded copy-on-write of at most16records. New tail capacities start at4and grow to16 under the existing admit-before-replacement rule. This avoids retaining one separately allocated chunk for every sequential append. Real chunk capacity, block metadata allowance and descriptor vectors are charged to the caller's admission callback.

The shared payload stays a private field of the same OrderedPixel as its mutable LinePool. New stage regions are created from that owner and carry only ranges of that same old region store. No key-table snapshot copy or whole-prefix validation scan occurs in this actual hot path. Existing line transactions preserve the committed key prefix; on failure temporary fragment owners drop and line IDs/table rollback together. The old state remains published until final successful commit. The separately checked BoundSnapshot adapters remain test-only; they are not the hot implementation.

Partial chunks may retain unused values. Automatic compaction/hybrid storage selection is not wired into this experimental backend. The checked prototype compactor is still separate. Actual allocations remain admission-bounded, but this is not a general memory-reduction or physical-RSS claim.
