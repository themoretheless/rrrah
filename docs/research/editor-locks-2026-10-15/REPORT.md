# Продолжение RR-0007–0010: блокировки и отказ recovery

2026-10-15. Все четыре задачи остаются `partial`; критерии приёмки не ослаблены.

Машинная сводка и снимок SHA: [qualification.json](qualification.json). Контрольные суммы файлов отчёта: [artifacts.json](artifacts.json).

## Реализовано

Существующая блокировка XMP полагалась на `create_new` и удаление файла в `Drop`. При принудительном завершении процесса `Drop` не выполняется, поэтому следующее сохранение отказывало из-за оставшегося файла. Теперь XMP и journal используют неблокирующий системный `File::try_lock`. Файл `.rrrah-lock-v2` остаётся на диске, его inode не удаляется; владение блокировкой освобождает ОС. Старый `.xmp.rrrah-lock` не удаляется автоматически и требует отдельного решения: он может принадлежать работающей старой версии.

При отказе чтения bounded recovery из-за изменившегося исходника, неизвестной схемы или повреждения редактор сохраняет исходный журнал и блокирует правки. `Ctrl/Cmd+Shift+N` либо одиннадцатая команда AccessKit/Tab явно начинает чистый сеанс. До замены journal точные исходные байты сохраняются в `.json.<BLAKE3>.retained` с `persist_noclobber` и синхронизацией. Повторное решение для тех же байтов использует ту же копию; несовпадающая существующая копия блокирует замену. XMP не меняется: для него по-прежнему нужно отдельное Save с проверкой digest.

Перед сбросом проверяются полный hash исходника и digest журнала; они проверяются повторно после создания копии. Неизвестная схема сохраняется как непрозрачные байты, без попытки миграции. Новый journal остаётся schema v1. Symlink, non-regular и документы сверх 256 KiB автоматически не сбрасываются. Работа с файлами выполняется на persistence actor, а не в обработчике клавиатуры. При попытке редактирования заблокированного документа статус сохраняет подсказку о доступном явном решении.

Во время разработки воспроизведён отдельный дефект нового reset при полностью занятом бюджете истории: [restart-budget-before.log](restart-budget-before.log). Создание второй EditSession отказывало после сохранения нового journal. Добавлен аддитивный `EditSession::reset`: он валидирует состояние до изменения, очищает undo/redo и gesture, устанавливает новый baseline и использует прежний admitted buffer. Регрессии проверяют успешный reset при полностью занятом бюджете, неизменность истории при invalid input и возврат кредита при Drop. Это исправление корректности бюджета, без заявления об ускорении.

## Проверки

[components.log](components.log): 25 native tests passed, 0 failed, 1 ignored helper. Harness включает текущие edit/histogram из rrrah-develop, текущие editor/edit_store/accessibility и реальный rrrah-memory; serde_json 1.0.151 с float_roundtrip.

Шесть subprocess kill-сценариев покрывают XMP/journal до persist, после persist и после синхронизации каталога. Пока дочерний writer работает, конкурирующая запись отклоняется. После kill читается целый старый/новый документ и следующая запись проходит без удаления lock-файла. Седьмой kill-сценарий останавливает явный reset после сохранения backup: исходный отказавший journal и его точная копия остаются целыми; повторная попытка использует ту же копию.

Отдельно проверены сохранение legacy lock, отказ при non-regular v2 lock, изменившемся journal/source и конфликтующей backup, явное решение в actor для изменившегося исходника/неизвестной схемы/повреждения, запрет обычных правок до решения и неизменность XMP.

[clippy.log](clippy.log): native-модули и их тесты проходят Clippy all+pedantic с прежними workspace allowances. Harness объявляет MSRV 1.92; это статическая проверка API compatibility, не запуск компилятора 1.92.

[app-check.log](app-check.log): актуальный manifest приложения проходит `cargo check -p rrrah --tests`. Ранее зафиксированные ошибки миграции CFA больше не воспроизводятся после параллельного разделения библиотек. [develop-tests.log](develop-tests.log): 3 `edit::tests` в настоящем rrrah-develop прошли, 96 остальных отфильтрованы. [app-tests.log](app-tests.log): 21 выбранный тест app binary с фильтром `edit` прошёл, 284 отфильтрованы, 3 ignored. ## Что остаётся

Реальный GUI/screen reader, Windows, сетевые файловые системы и отключение питания не квалифицированы. Advisory lock защищает только сотрудничающих writers; внешний writer может конкурировать с окончательным rename. Сосуществование старых и новых версий writer не квалифицировано; legacy lock автоматически не захватывается.

Нужны typed I/O errors, общий диалог внешнего изменения XMP, GUI kill-серия, политика хранения retained backups и безопасная очистка orphan temporary files. Полный hash редактора ещё не связан с допуском декодера; остаётся гонка между decode и открытием edit session. Dirty/failed история предыдущей загрузки сохраняется в bounded памяти без отдельного UI выбора. Shutdown всё ещё может ждать медленную файловую систему без верхнего срока. Графический редактор кривых, GPU/HDR/CUDA квалификация этим проходом не расширялись.

Параллельные изменения сохранены. Коммиты и публикация не выполнялись.
