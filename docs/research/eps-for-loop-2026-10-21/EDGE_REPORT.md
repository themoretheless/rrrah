# EPS for edge compatibility corrections

An additional independent Ghostscript10.05.1 pass exposed two real differences after the initial for implementation. With both initial and increment zero, Adobe/Ghostscript runs no body; the initial native implementation instead reached operand/work exhaustion. Integer counters truncate a real limit towardzero, so0,1,-0.5 and0,-1,0.5 each execute the integer0 iteration. The former native comparison against the fractional limit omitted it. The reproducing regression failed Limit(Operands) before correction (edge-red.log).

Native For dispatch now handles signedzero initial/step as an empty loop and truncates only the real bound of an integer counter. Real-counter mode explicitly converts all three operands to the VM's f32 precision, matching the independent reference. No body raster output or limit/cancellation check was weakened. A nonzero initial with zero increment still consumes work and refuses at the caller limit; its regression now uses1,0,2 rather than the reference-empty0,0,1 case.

Ascending and descending tenths traces match all independent f32 counter values, including accumulated rounding near endpoints. The large integer bound/real-step rounding case reaches the work limit instead of incorrectly skipping the loop, with temporary ownership released. Integer endpoint, nested-frame, admitted cancellation/retry and document stripe tests all remain passing. Current full suite240passed/0failed/11ignored; raw edge-reference logs retained. This corrects the initial report's generalization that every zero-increment range loops indefinitely; zero-initial plus zero-increment is the compatibility exception.

Primary reference implementation and its Adobe compatibility comment: https://github.com/ArtifexSoftware/ghostpdl/blob/gs10.05.1/psi/zcontrol.c . Used as behavioral evidence only; native Rust implementation remains independent. Broader PostScript and arbitrary EPS producer support remain incomplete.
