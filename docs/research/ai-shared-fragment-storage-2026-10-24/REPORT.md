# Shared immutable fragment storage primitive

The range-index trial still copied/materialized retained records and did not qualify a CPU/page benefit. This primitive instead stores immutable chunks of at most16actual Fragment values. New ranges retain Arc owners and copy only segment descriptors. A changed tail creates new chunks; old payload is never mutated. Descriptor vectors and new payload/block metadata allowances go through the existing Admitter callback before allocation; replacement descriptor capacity is admitted while old credit remains live. Checked lengths bound record/segment counts; operation/cancellation checkpoints bound block traversal.

The module is included under cfg(test) only, through ordered_pixel.rs. The preceding production body is byte-identical to its pre-prototype source; no normal renderer, work cap or public API is changed. The source is retained as the concrete next storage building block, rather than promoting an unqualified renderer rewrite.

## Integration boundary

Fragment edge tags are IDs into the owning OrderedPixel LinePool. This prototype preserves their numeric bits but does not retain or resolve the LinePool itself. Data remains inspectable after dropping the original partition; that is not proof of valid subsequent geometry replay. Integration must bind shared storage to the correct line-pool identity/lifetime and preserve transactional line-ID commits. It must also support shared runs beyond the prefix and test bounded retention/compaction of partial chunks, not merely append tails.

No AI page completion, normal viewer speed, real-budget pressure, GPU/Metal/HDR or NVIDIA claim follows from these tests. The next step remains integration of the immutable storage and context into the actual partition output, then exhaustive overlapping mutation/rollback and paired whole-kernel/real-file qualification. Full100-format scope remains open.
