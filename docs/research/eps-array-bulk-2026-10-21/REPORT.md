# Native EPS bulk data-array operations

Added aload/astore, getinterval/putinterval and the data-array form of copy while retaining integer stack-copy behavior. Array views share existing arena offsets/lengths without another allocation. A returned view keeps the evaluation's whole managed arena alive through its last owner; this is not a claim that unused parent storage is reclaimed. Array copy returns the copied prefix view of the destination, matching the independent reference.

All ranges and stack expansion are checked before data transfer. Copying uses direction-aware indexed traversal for overlap, with charged/cancellable work per element and no extra scratch allocation. getinterval and putinterval support valid zero-length ranges under the same range checks. astore preserves element order; aload appends the source array after its elements. This applies to native data arrays; strings/dictionaries and mutable executable procedure arrays remain outside the supported subset.

Independent Ghostscript10.05.1 traces match packing/unpacking, mutation through a view, right/left overlapping putinterval, copying into a larger destination, prefix-view identity and mutation through that returned prefix. Tests cover invalid intervals, short copy targets, astore underflow and aload operand overflow. Every observed checkpoint of a successful overlapping-copy program is replayed with cancellation; all failures release temporary credit, same-root retry yields exact values, and final root is0. Partial internal writes are never published because failed fresh VM execution returns no evaluation.

Six new8x8independent pixel references cover astore-built matrices, shared matrix views, both overlap directions controlling rectangle widths, returned copy-prefix matrices and aload-driven rectangle coordinates. They pass public decode/RAMeviction/swap/fullpressure/cancel/retry and32x32SDR/binary16HDR Metal equality, finalroot0. Reproduce with generate-eps-pixel-ghostscript-reference.py --array-bulk.
