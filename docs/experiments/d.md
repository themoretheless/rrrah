# Эксперимент D — цветовое ядро: f64-матрицы, диагностика G1/G2, luminance-нормализация WB

> Историческая запись. Численный эффект H2 реален, но его интерпретация как
> обязательной camera-space нормализации отменена после GPU readback:
> Rec.709 weights относятся к display RGB. Актуальное решение —
> [`DIRECT_WB_GPU_READBACK.md`](DIRECT_WB_GPU_READBACK.md).

Исполнитель: Исполнитель_D. Зона: `crates/rrrah-core/**` только.
Машина: Apple M5 (arm64), macOS 27.0. Дата прогона: см. git-таймстемп файла.

## Гипотезы

- **H1**: f32-инверсия 3×3 нестабильна на почти сингулярных матрицах (round-trip ошибка > 1e-5, контракт `docs/EDITOR_MATH.md:36,66`).
- **H2**: WB без нормализации по яркости сдвигает экспозицию.

## Что сделано (код)

1. **f64-ядро матриц** (`crates/rrrah-core/src/color.rs`):
   - `SRGB_TO_XYZ_D65_F64`, `multiply_3x3_f64`, `invert_3x3_f64` (отказ при `|det| < 1e-8` и нефинитных коэффициентах, как требует `EDITOR_MATH.md:35-36`);
   - `camera_to_linear_srgb_precise([[f64;3];4]) -> Result<[[f64;3];3], CameraProfileError>` — построение и инверсия профиля полностью в f64;
   - `bradford_adaptation_f64` — референс-точность для построения профилей;
   - легаси `camera_to_linear_srgb([[f32;3];4]) -> Option<[[f32;3];3]>` сохранён по сигнатуре (вызывается из `rrrah-gpu`), но теперь это тонкая обёртка над f64-путём с даункастом в f32 только на выходе (для uniform-загрузки). Поведение для `rrrah-gpu` не ломается: при отказе он по-прежнему падает в identity с `log::warn!` (`rrrah-gpu/src/lib.rs:1111-1114`).
2. **Диагностика G1/G2**:
   - `diagnose_green_planes(&[[f64;3];4]) -> GreenPlane { Absent, Consistent, Divergent(f64) }`;
   - плоскость 3 из нулей = G2 отсутствует; расхождение с плоскостью 1 свыше `GREEN_PLANE_RELATIVE_TOLERANCE = 1e-3 * max(1, max|G1|)` — отказ `CameraProfileError::GreenPlaneMismatch { max_abs_divergence, tolerance }` вместо молчаливого отбрасывания 4-й плоскости. Легаси-обёртка в этом случае тоже возвращает `None`.
3. **WB-функции** (чистые, готовы к подключению в шейдере — шейдер вне зоны):
   - `WB_LUMINANCE_WEIGHTS = [0.2126, 0.7152, 0.0722]`;
   - `green_relative_wb_gains` — `g_c = (WB_c / WB_G)^-1` (`EDITOR_MATH.md:24-26`);
   - `luminance_normalize_wb_gains` — делит гейны на их взвешенную яркость;
   - `display_wb_gains` — полная цепочка «мультипликаторы камеры → экспозиционно-нейтральные гейны». Все три отвергают нефинитные/неположительные входы.
4. **Тесты**: +11 unit-тестов в `color.rs` и параметрический корпус `crates/rrrah-core/tests/color_precision.rs` (12 матриц: sRGB↔XYZ, Bradford, 4 реалистичные камерные матрицы в стиле dcraw/Adobe `ColorMatrix`, 6 членов почти сингулярного семейства `eps = 1e-3..1e-8`).

## Метод

Round-trip ошибка = `max|M · M⁻¹ − I|`, для обоих путей вычислена в f64 (чтобы f32-путь мерялся против истинной арифметики, а не против самого себя). Почти сингулярное семейство: строки `r1, r2, 0.6·r1 + 0.4·r2 + eps·n` — база ранга 2, число обусловленности растёт как `1/eps`. Таблицы ниже — дословный вывод `cargo test -p rrrah-core --test color_precision -- --nocapture` (1 прогон; величины детерминированы, статистика прогонов не нужна).

| Bradford cone response | 1.790e0 | 5.503e-8 | 1.110e-16 | |
| camera A (DSLR daylight) | 9.673e-1 | 9.221e-8 | 3.331e-16 | |
| camera B (mirrorless tungsten) | 5.531e-1 | 7.518e-8 | 4.441e-16 | |
| camera C (compact, wide gamut) | 1.215e0 | 4.529e-8 | 3.331e-16 | |
| camera D (Foveon-like, strong cross-talk) | 3.262e0 | 1.350e-7 | 3.331e-16 | |
| near-singular eps=1e-3 | 5.135e-4 | 1.766e-5 | 1.137e-13 | **YES** |
| near-singular eps=1e-4 | 5.135e-5 | 9.933e-5 | 1.137e-13 | **YES** |
| near-singular eps=1e-5 | 5.135e-6 | 1.255e-3 | 3.638e-12 | **YES** |
| near-singular eps=1e-6 | 5.135e-7 | 1.107e-2 | 2.910e-11 | **YES** |
| near-singular eps=1e-7 | 5.135e-8 | 9.666e-2 | 4.657e-10 | **YES** |
| near-singular eps=1e-8 | 5.135e-9 | 5.597e-1 | rejected (det < 1e-8) | **YES** |

Итог: f32 round-trip > 1e-5 на 5 из 6 почти сингулярных матриц (на eps=1e-8 f32 вообще «инвертирует» с ошибкой 0.56 — детерминант после f32-округления случайно проходит порог); f64 держит ≤ 1.1e-13 вплоть до eps=1e-4 и остаётся на 4–8 порядков точнее f32 по всему семейству.

Согласие f64-пути с f32-обёрткой на здоровых профилях (max разница элементов): 2.8e-8 … 5.7e-8 (все < 1e-5).

### H2: WB без luminance-нормализации

| camera WB (as shot) | luma shift | stops |
|---|---|---|
| tungsten [1.9, 1.0, 1.4] | 0.8787 | −0.187 |
| shade [2.3, 1.0, 1.2] | 0.8678 | −0.205 |
| fluorescent [1.5, 1.0, 1.8] | 0.8970 | −0.157 |
| daylight [2.0, 1.0, 1.6] | 0.8666 | −0.207 |

Т.е. применение green-relative гейнов без нормализации занижает экспозицию на ~0.16–0.21 стопа на типичных illuminant'ах — систематический, зависящий от источника света сдвиг. После `luminance_normalize_wb_gains` взвешенная яркость гейнов = 1.0 с точностью < 1e-6.

## Вердикты

- **H1 — подтверждена.** Порог 1e-5 f32-путь пересекает уже при `|det| ≈ 5e-4` (число обусловленности ~1e3), т.е. задолго до зоны отказа по `|det| < 1e-8`. Контракт round-trip `<1e-10` f64 выполняется на всех здоровых матрицах (фактически ≤ 5e-16); f64-путь с даункастом в f32-uniform удовлетворяет `<1e-5`.
- **H2 — подтверждена.** Сдвиг −0.16…−0.21 стопа на типичных WB-мультипликаторах; функция нормализации устраняет его точно.
- **G1/G2**: молчаливая редукция устранена — расходящиеся плоскости теперь дают явный `CameraProfileError::GreenPlaneMismatch` (с величиной расхождения и порогом), согласованные (в т.ч. с шумом < 1e-3) принимаются, нулевая 4-я строка трактуется как отсутствие G2.
