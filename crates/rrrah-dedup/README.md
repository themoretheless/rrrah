# rrrah-dedup

Native Rust primitives for exact-file discovery, decoded-pixel equality and local visual-copy search. These results have different meanings: byte-confirmed groups identify equal files; decoded-pixel equality applies to the selected decoding contract; local visual support can identify a crop or embedded copy without making the whole files equal.

## Features

| Cargo feature | Capability |
| --- | --- |
| Default (none) | Exact-file scanner, fingerprints and matching primitives |
| `raster` | Operations on admitted raster payloads |
| `decode` | File decoding, guarded visual search and collections |
| `loftr` | Cached native CPU LoFTR provider; requires compatible libtorch and model weights |

## Exact files

Run a read-only recursive folder scan from the repository root:

```sh
cargo run --release -p rrrah-dedup --example scan_folder -- "/path/to/folder"
```

Pass multiple folders to find duplicates across them. The example prints byte-confirmed groups, physical-file aliases and diagnostics; it never deletes files. Symlinks are skipped by default and reported as `SymlinkSkipped`; this intentional exclusion still permits exit code 0. Inspect diagnostics even when the scan completes. Exit code 1 means the scan is incomplete (for example, an unreadable or changing file, or a resource limit); code 2 means no folder was supplied. Use `--help` for limits. For a relative folder named `--help` or `-h`, pass the example its own `--` separator: `cargo run --release -p rrrah-dedup --example scan_folder -- -- --help`.

To check a built example against an independent generated byte partition:

```sh
python3 scripts/check-dedup-folder-cli-oracle.py target/release/examples/scan_folder
```

The script uses its own temporary corpus (80 files, 11 duplicate groups), checks three root orders including overlap, and verifies that file contents stay unchanged. It also scans three relative folders named `--help`, `-h`, and `--`, each containing two duplicate files, using the executable's option terminator. It does not scan user folders or qualify visual matching, concurrent source changes, or other filesystems. Optional `--seed` changes the generated payloads; `--report PATH` saves a new report without replacing an existing one.

Boundary checks cover an empty folder (exit 0), a missing folder (exit 1), and missing arguments with or without the option terminator (exit 2). Mixed healthy/missing roots must retain every independently expected duplicate group from the healthy root in both argument orders while returning exit 1 and a diagnostic.

```rust
use rrrah_dedup::exact::{scan_verified, Options};
use std::path::PathBuf;

let options = Options {
    max_entries: 100_000,
    max_file_bytes: 512 * 1024 * 1024,
    ..Options::default()
};
let report = scan_verified(&[PathBuf::from("./images")], &options, || false);
if report.complete() {
    for group in &report.groups {
        println!("{} equal files, {} bytes each", group.paths.len(), group.bytes);
    }
}
// Surface report.issues and report.cancelled to the caller even with no groups.
// report.aliases describes multiple paths to the same physical file separately.
```

The scanner confirms full BLAKE3 hash equality with byte comparison. Traversal/resource omissions and changed files appear in diagnostics. Results are stable observations rather than an atomic filesystem snapshot. The scanner does not delete files.

## Decoded pixels and visual copies

With `decode`, use `scan::scan_equal_pixels` for direct selected-frame pixel comparison, or `pixel_index::scan_indexed_pixels` for indexed candidate discovery followed by pixel confirmation. A fingerprint or Hamming distance alone does not establish pixel or file equality. Decode requests must carry the appropriate frame/color/owner contract; unsupported sources and changes must remain visible to the caller.

For ordinary-bank search followed by calibrated exposure recovery, the explicit APIs are:

- `model_banks::search_model_banks_exposure_recovery_files_with`: one directed pair with a caller-supplied proposal provider.
- `model_banks::scan_model_banks_exposure_recovery_collection_with`: one canonical-ID direction per unordered collection pair.
- `model_banks::scan_model_banks_bidirectional_exposure_recovery_collection_with`: reverse the pair after an inconclusive forward result.
- `model_loftr::scan_loftr_model_banks_bidirectional_exposure_recovery_collection`: the same collection with one lazy CPU model cache (`loftr`).

Construct the bidirectional batch limits with `ModelBankExposureCollectionPolicy::for_bidirectional_pairs`; the one-direction constructor does not reserve reverse work. Both complete directed searches are admitted before input consumption, even when support permits skipping a suffix. Recipes and thresholds are explicit policy inputs, not a universal trained precision preset.

Collection reports retain every unordered pair, including inconclusive evidence. Forward transforms map lower-ID source to higher-ID target; reverse transforms map higher-ID source to lower-ID target. Keep this direction when using the geometry. Local visual support is nontransitive: do not infer duplicate groups by connecting supported pairs. Source/weight changes, owner/caller cancellation and provider errors discard the guarded collection rather than returning its supported prefix.

Keep the report alive while reading its borrowed pair slice; its managed storage credit is released on drop. `MemoryBudget` accounts for admitted payload/report storage. Provider tensors, model caches, snapshot metadata and other external allocations require separate process RSS qualification.

## Explicit RAW development

`DecodeRequest::raw_development_recipe` selects `RawDevelopmentRecipe::NativeDefault` (the unchanged default) or `Bilinear` for full-resolution sensor development in the dedup selected-frame APIs. The recipe is part of fingerprint cache identity, including persisted entries. Raster decoding and sensor extraction do not apply demosaicing. Matching the same development algorithm is not general cross-development equality or precision qualification.

The `raw_raster_probe` example accepts `RRRAH_RAW_RECIPE=bilinear` (or `native-default`) for spatial pair comparisons and known-shift comparisons with `RRRAH_FILE_WHITE_ANCHOR=1`. This selects the ordinary file request recipe; unsupported modes and invalid values are rejected. For spatial collection checks, set `RRRAH_VERIFY_COLLECTION=1` and optionally supply newline-separated paths in `RRRAH_COLLECTION_PATHS`; each request receives the selected RAW recipe. This does not change the scanner default.


## Experimental white-anchored display evidence

`warp::verify_photometric_white_anchored_display_projection` compares caller-supplied linear RGBA views and geometry. It fits `offset = 1 - gain` independently in both directions, using opaque RGB samples in `[0, 1]`, within the declared gain and offset bounds. Residual verification retains the full overlap, including highlights and alpha differences; the report also retains the strict, unadjusted pixel evidence. Flat or insufficient fitting samples, invalid bounds, work limits and cancellation remain explicit errors.

`warp::verify_reflected_photometric_white_anchored_display_projection` provides the corresponding orientation-reversing similarity primitive. Reflection uses the caller's coordinate transform (for a horizontal flip of a width-W image, `a=1`, `b=0`, `translation=[W-1, 0]`); this API does not discover geometry.


This opt-in primitive is not exact identity or a file/collection search recipe. Callers must assess overlap and residual evidence in both directions. It is not used by the default scanner. Filtered comparison requires explicitly selecting `PhotometricFitMode::WhiteAnchoredLeastSquares`; its tolerance is in the selected color space, and window averaging can suppress small edits. Synthetic regressions and two fixed-geometry Sony diagnostics do not qualify general RAW development matching or difficult-negative precision.

With `decode`, `white_anchored_file::verify_white_anchored_files` provides the experimental selected-frame file adapter with explicit decode limits and a `MemoryBudget`. It retains source/dependency observations across the comparison and checks for changes after the last user callback. It still requires caller-supplied geometry and does not discover duplicate groups.

`local_scan::compare_local_files_white_anchored` also discovers pair geometry from local features, optionally using a spatial feature grid, before applying the same constrained photometric model. It retains strict pixel evidence and source-change checks. This opt-in pair API returns similarity candidates; it does not establish byte equality. Two Sony RAW/linear-TIFF pairs using explicit Bilinear development passed automatic geometry qualification; two cross-scene orders were rejected without geometry. These finite controls do not establish general precision or cross-development coverage. See the [recorded automatic comparison](../../docs/research/dedup-500/sony-display-matrix-20261026-v1/auto-explicit-bilinear-20261026.json).

`LocalComparisonMode::WhiteAnchoredDisplay(photometric_policy)` selects the same model through `LocalSearchPolicy` for pair and indexed collection APIs, including reflected comparisons. The declared fitting range is `[0, 1]`; strict original pixel residuals remain in the report. Collection descriptor retrieval can omit pairs before pixel confirmation, so pair-level agreement alone does not prove collection recall. The `raw_raster_probe` example selects this collection mode when both `RRRAH_AUTO_WHITE_ANCHOR=1` and `RRRAH_VERIFY_COLLECTION=1` are set.

Authored collection regressions compare both ordinary and reflected indexed results against individual pair confirmation: a small local edit remains a similarity candidate with strict differences retained, while a quarter-image edit is rejected with valid geometry. A mirrored copy is accepted and a mirrored quarter-image edit rejected. These fixtures do not establish corpus-wide precision.


The automatic white-anchor cancellation regression normally samples 128 callback positions, including both endpoints, checks a one-shot cancellation pulse, releases managed memory, and retries. Set `RRRAH_EXHAUSTIVE_AUTO_CANCEL=1` when running `local_final_callback::automatic_white_anchor_cancellation_sweep_and_retry` for the full pixel-level callback sweep; this is a dedicated long-running check.



## Coverage evidence

The [coverage contract](../../docs/DUPLICATE_LIBRARY_CONTRACT.md) records exact scope, frozen test sources, CPU controls and remaining requirements. The [research registry](../../docs/research/dedup-500/REPOSITORIES.md) is a candidate inventory; it does not establish full source review of all 500 repositories. Full corpus recall, held-out difficult negatives, format/platform coverage and total resource bounds remain separate acceptance requirements.

A four-file Sony RAW/independent linear-TIFF indexed check with explicit Bilinear development proposed all six pairs, accepted both labelled same-scene pairs and rejected four cross-scene pairs without geometry. Projected matched-pixel counts matched stored pair controls. This two-scene result does not qualify broad precision; raw logs and input hashes are in `docs/research/dedup-500/sony-display-matrix-20261026-v1/real-sony-indexed-white-anchor-20261026.json`.

Same-binary reverse/interleaved order controls retained both labelled Sony scene pairs, including TIFF-first comparisons, without extra candidates. TIFF-first managed peak was about 1340 MiB, compared with about 970 MiB for the original RAW-first order; this is managed accounting, not process RSS. See `real-sony-indexed-order-20261026.json` in the same evidence directory.

Ordinary/reflected local pair confirmation now develops a sensor peer before retaining a raster peer, while preserving caller view order. On alternating before/after Sony collection controls, TIFF-first managed peak fell from 1,404,919,168 to 1,017,069,952 bytes (about 370 MiB, 27.6%); every non-memory output line was identical in both reversed and interleaved orders. This is managed-allocation evidence for two scenes, not RSS or throughput qualification. See `sensor-first-indexed-order-20261026.json` in the evidence directory.

`raw_raster_probe` accepts `RRRAH_MANAGED_BUDGET_MIB` as a positive integer (default 2048); zero, invalid and overflowing values fail before source IO. In the four-file TIFF-first Sony check, 1000 MiB retained both expected candidates and a 900 MiB cap returned explicit per-file RAW capacity failures with managed memory released. The collection example now prints the full report and exits nonzero when `file_issues`, `pair_issues` or `source_issues` are nonempty; a complete search with no candidates remains successful. The corrected exit-status controls are in `real-sony-budget-exit-20261026.json`; `real-sony-budget-20261026.json` retains the earlier behavior for comparison.

A mixed-input control adds a nonexistent fifth path to the four Sony files: both healthy same-scene pairs are retained, the missing input is identified in `source_issues`, managed memory is released, and the collection example exits 1. See `real-sony-mixed-missing-source-20261026.json` in the evidence directory.

A repeated-content collection control uses one Sony RAW, its independent TIFF rendering and a byte-confirmed TIFF copy at a distinct path. All three pair candidates are retained; RAW-to-original/copy evidence is identical and the TIFF copy pair has full strict-grid agreement. This finite case does not make visual support transitive. Evidence and the executed driver are stored under `real-sony-repeated-content-20261026.json`.

`sensor_first_pair_admission_avoids_retaining_raster_during_raw_scratch` is an automatic finite resource regression: an authored DNG/BMP pair uses a cap derived from isolated RAW peak, reproduces raster-first allocation refusal, then verifies successful local-pair admission in both caller orders and full managed-memory release. Its tiny RAW has no usable geometry; this test does not qualify visual similarity.

The authored mixed-format budget regression also covers reflected local pairs in both caller orders, checks single-pulse cancellation at first/middle/final callback positions, requires the cancellation error and zero retained managed memory, and verifies a successful retry. It samples cancellation positions rather than exhaustively testing every callback.

`cargo run --release -p rrrah-dedup --features decode --example selected_frame_compare -- LEFT RIGHT [LEFT_INDEX] [RIGHT_INDEX]` performs direct in-memory selected-frame equality with bounded decoding and reports digests, dimensions and frame metadata. A completed unequal comparison exits zero with `selected_frame_equal=false`; decoding/usage errors exit nonzero. This is not whole-file identity or an atomic filesystem observation. All three PNG-backed entries of the pinned upbrr ICO matched their exact extracted PNGs; mismatched-size entries compared unequal and an out-of-range index was rejected. See `docs/research/dedup-500/evidence/autobrr--upbrr/ico-selected-frame-qualification-20261026.json`.

The bounded selected-frame API checks the decoder-reported container image count against `max_frames`, including native ICO results. TIFF separately bounds directory traversal before page decode; the generic native check occurs after decoding and does not establish an early parser-work bound. Fingerprint domain v8 separates cached results from earlier frame-admission and container-dispatch rules. Authored DIB-backed ICO tests cover 24/32-bit pixels, straight alpha, a bottom-up AND mask, selected metadata and limit refusals; they do not qualify the full icon/cursor grammar.

ICO/CUR directory counts are also checked from a bounded header before native pixel allocation. DICOM `DICM` markers take precedence over misleading TIFF/ICO/CUR signatures in the arbitrary 128-byte preamble; this mirrors native format routing. This protects selected-frame dispatch and does not turn DICOM stored measurements into display-ready colors: unsupported color transforms remain explicit errors.

Persisted ICO fingerprint tests independently admit each selected DIB frame, save/reload the cache, refuse a stricter frame-count policy and retain valid warm entries for retry under the original policy. These finite controls do not qualify crash durability or every historical cache version.
